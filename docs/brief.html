FedCast: the brief

A forecaster for the next Federal Reserve rate decision, built to be judged by its process rather than its luck.

Status as of 25 October 2026 · next decision 28 October 2026 · repository kmt112/fed-forecast · ledger entry #13

The thesis

A large language model inside an engineered harness produces forecasts that are measurably more repeatable and more faithful to evidence than the same model asked naively. The way to prove that is not to wait for the forecasts to come true (eight decisions a year is far too few, and the market is already very good at this) but to measure the process: does the same question get the same answer, can every claim be traced to evidence, does any number come from memory, does a shock to one input move the answer the right way, does an irrelevant change leave it alone, does human input flow only through channels that can be audited.

1. The thought process

Five principles were fixed at the start and everything since has been built to honour them.

  1. Process over outcome. Accuracy is logged after each decision and never used to tune anything. A system that is right for the wrong reasons would have been found out eventually; one that is disciplined can be trusted before the record exists.
  2. Pre-register, then amend in the open. The ten-dimension scorecard, the pool weights, the surprise floor, every model rule that can move the number and every fitted model's specification were written down before use. Changes are numbered amendments with reasons, and a hash of the spec is pinned in the test suite so a silent change breaks the build. Six amendments so far (#0 to #5).
  3. Frozen evidence. Every forecast runs on one fingerprinted snapshot of evidence, dated in US time. Models and analysts may read nothing else: no internet, no memory. Historical fits use data exactly as it was first published, never today's revised figures.
  4. Code computes, models read, code checks. Anything that can be arithmetic is arithmetic. Language models are used only for what arithmetic cannot do, reading text and weighing arguments, and everything they produce is verified by code before it counts.
  5. Human judgement through typed channels only. You can lean the forecast, add standing instructions, add your own documents and enter prediction-market odds, but each is a typed, bounded, recorded input. Nothing moves the number silently.

Read the ladder left to right. Showing the model the evidence (B) removes the stale memory and the leaked numbers, but the answer still wobbles by 2 to 3 points between identical runs and nothing in it can be checked. Forcing a schema with a quote per claim and checking every quote by code (C) is what makes the output stable and verifiable. Splitting the reading across specialists (D) keeps those properties, makes each judgement attributable to its slice of evidence, and lets one dissent (labour) survive instead of being averaged away inside one head. Same model, same day; the difference is the harness.

What the replay check found, and what was done about it

Recomputing every ledger entry showed three groups. Entries #0 to #3 were recorded under earlier pool weights and no longer match, as the amendment log says they should not. Entries #4 to #6, #11 and #12 give back their numbers exactly. Entries #7 to #10 did not, although they carried the current spec hash: amendment #4 had changed how stale prediction-market odds are treated, a model rule that was not part of the hashed spec. That is a governance gap. Amendment #5 (25 October) closes it: every model rule that can move the number is now inside the spec hash, so a rule change forces a new hash and a logged entry, and entries recorded under an earlier spec are labelled rather than quietly failing. No weight, floor or rule changed. Entry #13 is the first under the new hash and replays exactly.

The quant side's own test

The first ordered probit, with its spec frozen in advance, failed its out-of-sample gate (log score −1.14 against −0.71 for a simple base rate) and was reported as such rather than tuned. A pre-registered v2 beats the base rate on an expanding-window evaluation (−0.47 against −0.58) but carries a declared contamination caveat, so it stays outside the pool until live decisions judge it. The historical base rates, which need no fitting, beat the probit v1 and are the natural yardstick.

6. How to read the app in two minutes

  1. Top bar: when the evidence was last pulled, and what is new at the sources since.
  2. Forecast: the machine number and the number after your views, side by side.
  3. Evidence graph: click any box. Blue is in the number; grey is computed but not in it; dotted is planned. Click a model to see only what it uses.
  4. Agents: what each of the eight agents is asked and shown, down to the full prompt. If it is not on that page, the agent does not get it.
  5. Analysts: what each agent concluded on this snapshot, every claim with its quote and a verified or not-found mark.
  6. Scorecard: the yardstick; the measurements against it on any snapshot you pick (hover a cell for what was counted); every recorded run on that snapshot; and the over-time table that shows whether anything has drifted.
