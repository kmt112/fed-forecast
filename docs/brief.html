FedCast: the brief

A forecaster for the next Federal Reserve rate decision, built to be judged by its process rather than its luck.

Status as of 19 October 2026 · next decision 28 October 2026 · repository kmt112/fed-forecast

The thesis

A large language model inside an engineered harness produces forecasts that are measurably more repeatable and more faithful to evidence than the same model asked naively. The way to prove that is not to wait for the forecasts to come true (eight decisions a year is far too few, and the market is already very good at this) but to measure the process: does the same question get the same answer, can every claim be traced to evidence, does any number come from memory, does human input flow only through channels that can be audited.

1. The thought process

Five principles were fixed at the start and everything since has been built to honour them.

  1. Process over outcome. Accuracy is logged after each decision and never used to tune anything. A system that is right for the wrong reasons would have been found out eventually; one that is disciplined can be trusted before the record exists.
  2. Pre-register, then amend in the open. The ten-dimension scorecard, the pool weights, the surprise floor and every fitted model's specification were written down before use. Changes are numbered amendments with reasons, and a hash of the spec is pinned in the test suite so a silent change breaks the build. Five amendments so far.
  3. Frozen evidence. Every forecast runs on one fingerprinted snapshot of evidence, dated in US time. Models and analysts may read nothing else: no internet, no memory. Historical fits use data exactly as it was first published, never today's revised figures.
  4. Code computes, models read, code checks. Anything that can be arithmetic is arithmetic. Language models are used only for what arithmetic cannot do, reading text and weighing arguments, and everything they produce is verified by code before it counts.
  5. Human judgement through typed channels only. You can lean the forecast, add standing instructions, add your own documents and enter prediction-market odds, but each is a typed, bounded, recorded input. Nothing moves the number silently.

2. What has been built

doneEvidence layer

Pull evidence freezes 21 items: the FOMC calendar, the overnight rate, fed-funds futures, eight FRED series as published on the day, both latest statements, the minutes, the press-conference transcript, the projections table, every speech since the last decision, 32 years of decision history, and your own inputs. Every item links to its original and to the frozen text the models saw. An update check says what the sources have that the snapshot does not.

doneSignals (computed, shown)

Inflation gap and momentum with a nowcast; labour slack; financial conditions; communication tone (vote, statement word-diff, lexicon); base rates from 256 decisions since 1994; committee projections. Each box on the evidence graph explains what it is, why it matters and how it is computed, with today's numbers.

doneModels and pool

In the pool: market-implied (0.7), the Fed's own four Taylor rules (0.2), hand-entered prediction-market odds (0.1), a 1.5% surprise floor. Computed but outside the pool pending evidence: historical base rates, and an ordered probit fitted on first-published data with an expanding-window evaluation. The pool is a fixed weighted average done in code.

doneLLM analysts

Five specialists plus controls, each seeing only its slice of the snapshot with every tool disabled, answering in a fixed schema with a verbatim quote per claim and a tilt bounded to ±10 bp. Code verifies every quote, number and watch-out; every run is recorded and replayable. Ablation arms A to D exist; E and F are planned.

doneGovernance and audit

An append-only, hash-chained ledger of forecasts that must recompute exactly from their snapshots; an amendment log; a measured scorecard per snapshot; an audit view of every analyst run with its scores; everything committed to git.

doneThe app

A local web app: Forecast, Evidence graph (click a model to see only what it uses), Your input, Methodology, Ledger, Scorecard, Analysts and Audit views. Runs on this machine or any clone; a cloud session can run everything but the page.

The naive prompt still believes the Fed is cutting (its memory is stale) and moves by three points between runs. The specialists converge on a mild hawkish lean (+4.4 bp average) that quotes the September hike, the unanimous vote, the minutes' tightening bias and the committee's own projections. Same model; the difference is the harness.

The quant side has had its own test. The first ordered probit, with its spec frozen in advance, failed its out-of-sample gate (log score −1.14 against −0.71 for a simple base rate) and was reported as such rather than tuned. A pre-registered v2 beats the base rate on an expanding-window evaluation (−0.47 against −0.58) but carries a declared contamination caveat, so it stays outside the pool until live decisions judge it.

Current forecast for 28 October (ledger entry #11): no change 62%, +25 bps 33%, with the market as the anchor.

5. How to read the app in two minutes

  1. Top bar: when the evidence was last pulled, and what is new at the sources since.
  2. Forecast: the machine number and the number after your views, side by side.
  3. Evidence graph: click any box. Blue is in the number; grey is computed but not in it; dotted is planned. Click a model to see only what it uses.
  4. Analysts: what each specialist concluded on this snapshot, every claim with its quote and a verified or not-found mark.
  5. Scorecard and Audit: the yardstick, the measurements against it, and every recorded run over time.
